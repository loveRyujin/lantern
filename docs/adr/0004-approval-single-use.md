# ADR 0004：确认单只用一次，失败后要重新确认

## 状态

已接受（2026-10-21）。对应审批状态机。有副作用的动作，宁可再问一次，也不要在本人不知道的情况下再跑一遍。

## 背景

批准之后，循环在执行前把确认单从 `approved` 消费成 `consumed`。工具如果在这之后失败，确认单已经用过了。自动用同一张单再试一次，等于没再问人就又做了一次副作用。

## 决策

一张确认单最多执行一次。`consumed` 是终态。运行失败不会把它改回 `approved`。

工具失败后，模型如果要再试，必须发起一次新的调用。新调用会新建一张确认单，并再次经过本人批准。循环不会拿旧确认单自动重跑，同一次调用里的 `MaxAttempts` 也不再重试已经消费的单。

失败结果和原来的确认单标识一起写入两处：`run_events`，以及审计日志。两处都不放参数原文。

同一个决定再提交一次是幂等成功：返回第一次的结果，`duplicate=true`，不改状态、不改版本、不再执行，并追加一条 `duplicate_decision` 审计。换成另一个决定仍然是非法转移。

替换参数不符合 Schema 时不执行，校验错误回到用户，不交给模型，也不计入连续失败。确认单保持 `pending`、未消费，用户可以在 `expires_at` 之前重新提交。

## 后果

- 消费成功但工具失败时，这次副作用不会自动再来一次。用户会在下一次调用里再看到确认。
- 审计和 `run_events` 都能按确认单标识把失败和那张单对上。
- 重复点击同一个批准不会多执行一次，也不会把版本号再加一。
