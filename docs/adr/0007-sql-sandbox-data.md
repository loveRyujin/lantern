# ADR 0007：SQL 观察值的无损 CSV 输入与产物内容边界

## 状态

实现与验收中（2026-10-23），对应 #42。依赖 #41 的真实 Linux Runner；本轮不注册 #43 的生产 run_python 工具，不将测试适配器称为生产接入。

## 问题与选择

CSV 本身不携带 NULL 或数字类型。直接 fmt.Sprint、空串代替 NULL、pandas 自动推断会分别丢失数值精度、混淆空值，或把带前导零的字符串改成数字。重复列名也不能交给字典读取，否则同名列互相覆盖。

独立 `core/analysisdata` 适配层只接受已经成功执行的生产 run_sql 的 Content JSON，不重新访问数据库，不依赖低层 Query。源观察值最多 1 MiB、32 列、1000 行，校验实际行数、每行宽度、字段类型和截断信息；JSON 数字以 json.Number 原词传输，不转换为 float64 后序列化。有限性检查会解析 float64，但检查结果不用于传输，因此大整数不会被舍入。

输出 `table.csv` 使用稳定位置 ID 表头 c0、c1……，每个单元格先编码为紧凑 JSON，再交给标准 CSV writer 处理逗号、引号及换行。`table.meta.json` 保存版本、编码、位置与原列名、实际行数及源截断信息；不猜测原查询总行数。JSON null、空字符串、文本 null、整数与数字字符串保持不同。原产品协议已把 BLOB 表示成 base64 字符串，因此本层不能臆测恢复 SQLite 存储类型；非法 UTF-8 TEXT 沿用原标签对象。

固定 Python reader 按位置读取 CSV，再使用 json.loads 恢复单元格，整数为 int，小数/指数为 Decimal。不能使用 eval、pickle 或自动类型推断。Python csv 默认字段上限小于可能的合法 SQL 观察值，reader 必须显式设置有界字段上限。Python -I 下通过 runpy.run_path 加载只读输入中的固定 helper，而不依赖工作目录导入。

## 存储、预算与原子性

适配层仅返回独立内存字节，不创建共享中间文件。输入合计不超过 16 MiB，沿用 Runner 的文件数量、路径长度与路径元数据预算；metadata 文件内容与路径元数据是不同口径。取消或校验失败返回空结果，不能留下半张表。

可信业务调用方将 Runner.TempRoot 配置为当前工作区专属执行根；每次 Run 在其中创建独立目录，输入只读，只有 out/tmp 可写。默认临时目录不能被描述为已落入工作区。底层适配层不接受模型提供的宿主路径或扩大权限。

## 产物内容与路径

单件仍为 5 MiB、合计 20 MiB、最多 16 件。产物按扩展名和实际内容共同验证：

- PNG 先 DecodeConfig，单边最多 8192、总像素最多 4,000,000，再完整解码验证压缩数据/CRC。按 chunk 长度找到首次 IEND，必须恰好到 EOF，拒绝尾随内容及拼接图片。像素限制约束原始像素存储，不声称是 decoder 的全部内存峰值。
- CSV 必须 UTF-8、无 NUL，严格引号与一致字段数，至少一条记录。CSV 无魔数，单列普通文本也属于合法 CSV，不能声称内容检查能推断所有业务语义。
- JSON 必须 UTF-8 且语法有效，不额外约束顶层形状。json.Valid 本身不能代替 UTF-8 校验。

先停止并回收 Python，再遍历输出目录；O_NOFOLLOW 打开并 fstat 验证普通文件和 Nlink=1，拒绝符号链接、硬链接、目录与特殊文件。任何一件不合规则不返回部分产物。字节全部复制后才清理，返回值不引用已经删除的路径。

## 验收出口

独立测试须走真实生产 SQL Tool → 适配层 → 真实 Linux Runner → PNG/CSV/JSON 字节，覆盖 NULL/空串、重复/空列名、Unicode/逗号/换行、大整数、编码标签、截断，以及成功/失败/超时/取消清理与恢复。适当真实 Agent loop 集成不等于 #43 工具已完成。

移除关键内容/链接防护应在目标断言失败，不把编译错误或测试超时当作变异证据。最终提交完整 CI、GitHub 审查正文、三角色验收、合并/main 验证与 lantern-notes 同轮同步后，才关闭 #42。

真实链路初测发现启动期取消早于 launcher Ready 时，缺失 Ready 会把取消误分类为 sandbox_unavailable。修复在 guardian 完成 Wait/清理后优先检查调用 context，返回 timeout 且不交付产物；保留 Usage 供诊断。验收同时保留启动期和 Python 已执行后的取消，不能只移动同步点避开失败。

首轮真实链路还出现一次 sql_worker_failed，随后独立复跑 80 次未再现，原始偶发尚未归因。源码复核发现确定的另一个生命周期隐患：SQL worker 设置 Pdeathsig，但 Start→Wait 未固定创建 OS 线程。独立临时副本通过让非 leader 创建线程退出，证实真实 worker 被 signal:killed；这只证明机制风险，不等于认定原始偶发的根因。生产路径现锁定创建线程直到 Wait 完成，正常/失败/取消统一释放，保留父死保护、资源限制与错误分类，不重试或绕过子进程。
