# 云杉家居指标口径手册

本手册只适用于工作区「云杉」。金额在库里以分存储，对用户展示时除以 100，保留两位小数。订单时间取 `orders.created_at`，时区为 UTC。自然月按 UTC 切分，例如 2026 年 9 月是 `created_at >= '2026-09-01T00:00:00Z' AND created_at < '2026-10-01T00:00:00Z'`。

示例订单落在 2025-10-01（含）到 2026-10-01（不含）。问「上个月」且当前理解成 2026 年 10 月时，对应 2026 年 9 月。

## GMV

GMV 等于已支付订单金额减去这些订单的退款金额。状态为「已取消」或「待支付」的订单不进入减法的两边。一笔已支付订单后来全额退款，它对 GMV 的贡献为 0，订单本身仍算一笔已支付订单。

```sql
SELECT COALESCE(SUM(o.amount_cents), 0) - COALESCE(SUM(r.refund_cents), 0) AS gmv_cents
FROM orders AS o
LEFT JOIN (
    SELECT order_id, SUM(amount_cents) AS refund_cents
    FROM refunds
    GROUP BY order_id
) AS r ON r.order_id = o.id
WHERE o.status = '已支付'
  AND o.created_at >= '2026-09-01T00:00:00Z'
  AND o.created_at < '2026-10-01T00:00:00Z';
```

## 净销售额

云杉的净销售额与 GMV 是同一个数。GMV 已经扣除退款，不要再减一次。

## 客单价

客单价 = GMV / 已支付订单数。分母包含后来全额退款、对 GMV 贡献为 0 的已支付订单。除法与 SQLite 整数除法一致：单位为分，丢掉余数。已支付订单数为 0 时不计算。

## 复购率

复购率 = 统计期内已支付订单不少于 2 笔的用户数 / 统计期内至少有 1 笔已支付订单的用户数。全额退款的订单仍算已支付。分母为 0 时不计算。回答时同时给出分子和分母。

## 退款率

整体退款率 = 已支付订单上的退款金额 / 这些订单退款前的 `amount_cents` 之和。分母是退款前的已支付金额，不是 GMV。分母为 0 时不计算。

商品退款率 = 含该商品且该订单存在退款的已支付订单数 / 含该商品的已支付订单数。同一订单里同一商品出现多次只计 1 个订单。「退款率超过 15%」指这个比率大于 0.15。

```sql
SELECT i.product_id,
       COUNT(DISTINCT CASE WHEN r.order_id IS NOT NULL THEN o.id END) * 1.0
           / COUNT(DISTINCT o.id) AS refund_rate
FROM order_items AS i
JOIN orders AS o ON o.id = i.order_id
LEFT JOIN refunds AS r ON r.order_id = o.id
WHERE o.status = '已支付'
GROUP BY i.product_id;
```

## 区域

区域不是字段，按 `users.city` 归类。

| 区域 | 城市 |
| --- | --- |
| 华东 | 上海、杭州、南京、宁波、苏州 |
| 华南 | 广州、深圳、厦门、佛山 |
| 华北 | 北京、天津、青岛 |
| 西南 | 成都、重庆、昆明 |
| 华中 | 武汉、长沙、郑州 |

华东 GMV 在 GMV 的过滤条件上增加 `users.city IN ('上海', '杭州', '南京', '宁波', '苏州')`，订单经 `orders.user_id = users.id` 连接。

## 环比

环比 =（本期 − 上期）/ 上期。上期为 0 时只报告本期数值，不计算比率。按渠道拆分时，示例数据没有渠道字段，直接说明无法按渠道拆分，不要编造列名。

## 支付时间

分析库没有单独的支付时间列。已支付订单用 `orders.created_at` 作为支付时间。
